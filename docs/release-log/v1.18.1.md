# TokenPak v1.18.1 Release Log

## Scope

This minimum-diff hotfix restores Spend Guard approvals for the documented
Codex integration. It resolves Codex session headers, parses strict approval
intent and TIP directives from OpenAI Responses input, scopes pending and
anti-loop state per session, and prevents identity-less requests from creating
a global approval row.

## Hotfix notes

- **Triggering release:** v1.18.0
- **Hotfix rationale:** A valid Spend Guard approval from Codex repeatedly
  returned HTTP 402 because the parser did not understand Responses input and
  the held request used an empty global session key. This made a documented
  client integration non-functional during active work.
- **Validation shortened:** Upgrade-path and container checks were outside this
  minimum-diff hotfix because it changed no installed-state schema, container
  surface, public API, configuration, storage format, or TIP schema. Build,
  clean install, startup, proxy core, Codex user journey, regression, rollback,
  and full post-deploy validation remained required and passed.
- **Follow-up by 2026-08-10:** Run the remaining non-blocking validation breadth,
  publish the root-cause review, and separately decide whether model
  context-window metadata needs an update.

## Exceptions / waivers

- The test package index was unavailable. The exact release artifacts instead
  passed locked build, checksum, clean-install, CLI, startup, user-journey,
  version, and rollback checks before publication.
- Initial documentation and website propagation required the documented manual
  fallback. The live content was retained, a reviewed identity correction was
  deployed, and a fresh post-convergence watch covered the delayed path.
