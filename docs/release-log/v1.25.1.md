# TokenPak v1.25.1 Release Log

## Scope

The release adds `tokenpak savings --verify`, using an independent tokenizer
over a packaged fixture corpus. It reports divergence from the existing byte
estimator without changing recorded savings or claiming to recount requests
whose text was not retained.

Pricing catalogs include current model identifiers, explicit units, provenance,
and a preserve-first refresh path. Legacy numeric interpretations and existing
cost history remain intact. Forecast inputs preserve model and effort identity;
mixed histories and unsupported effort values remain unavailable for homogeneous
calibration. Session inactivity is not evidence of task completion.

Automatic vault retrieval has a configurable 2,000 ms deadline and a two-worker
bound. Timeouts and occupied-worker backlogs forward original request bytes and
produce explicit degradation receipts. All forwarding builders apply the same
internal-header predicate.

Companion and optional Pak-builder changes preserve role-bearing conversation
turns, isolate concurrent native launches, compose custom hooks, and retain
semantic journal provenance. Customized skills remain preserved during managed
upgrades. Session displays label estimates and distinguish guard runway from
session remainder.

Installed distributions carry canonical release metadata. The optional local
daemon must pass a bounded loopback health/version handshake with valid declared
compatibility before a client reports it active. Missing or incompatible daemon
metadata is shown as a diagnostic; the separately distributed Pro package is
not bundled into this OSS release.

## Compatibility and limitations

- The package version advances to 1.25.1. TIP-1.0 and its exact normative docs and
  schema pins remain unchanged.
- Pricing refresh preserves stored cost rows and old-date numeric interpretation.
  The existing reprocess pricing-version override remains ineffective.
- Forecast calibration, measured production reroute policies, and human
  comprehension outcomes require their own evidence. These source changes do
  not enable default-on rerouting or establish product-outcome claims.
- The existing NLTK advisory CVE-2026-81726 remains open for the optional
  `compression` and `llamaindex` extras; the current advisory lists no patched
  version. NLTK is not a base dependency.
- No breaking API or storage change is identified. The public API comparison
  with 1.24.0 adds 27 symbols and removes none; the telemetry schema is unchanged.

## Upgrade

```bash
python -m pip install --upgrade "tokenpak==1.25.1"
```

Install `tokenpak[tokens]==1.25.1` to use independent estimator verification.
Existing state and custom configuration are retained. Before upgrading a paired
daemon installation, install a Pro version whose declared compatibility includes
this OSS version and TIP-1.0. The prepared Pro 0.2.0 release declares exactly
OSS 1.25.1 and TIP-1.0. Wait for that separately published package before upgrading
a paired production installation; use the authenticated private index as usual.

## Rollback

```bash
python -m pip install --upgrade "tokenpak==1.24.0"
```

Keep the previous environment and configuration backup until validation and the
post-deploy watch finish. For paired installations restore Pro 0.1.6 with OSS
1.24.0. The isolated artifact upgrade and rollback retained all 19 representative
pricing rows, including a custom rate, and the exact configuration hash.

## Validation and release stages

Version 1.25.0 was tagged but never published. Its immutable tag-push run
[34149067045](https://github.com/tokenpak/tokenpak/actions/runs/34149067045)
failed in all four slim environments: an optional FastAPI import blocked test
collection, and two archive fixtures needed the absent build frontend. Each
slim job reported three errors. The failed tag and release log are preserved.

This correction keeps core pricing assertions available without FastAPI and
skips only the HTTP test when its dependency is absent. Archive construction
checks require the build frontend. The actual minimal environment has neither
dependency: 40 affected tests pass, three specific dependency skips are reported,
and one known pricing-reprocess expected failure remains. In development all
43 affected tests pass, including the HTTP and archive assertions, with the same
known expected failure. A further 185 version, daemon, endpoint and documentation
tests pass. Changed Python files pass the hosted lint/format tool version.

The API snapshot matches the source, with no symbol changes from the retired
1.25.0 candidate and 27 additions with no removals relative to published 1.24.0.
The telemetry schema and normative TIP pins remain unchanged. The prior compact
regression and four native Claude launch checks remain evidence for the
unchanged production changes, with their original failures and corrections
retained in the 1.25.0 log. They are not relabeled as current candidate runs.

Preliminary 1.25.1 wheel and source archives pass metadata, contents, exclusion,
public-leak and five baseline checks. Installed-wheel clean installation,
CLI help, doctor, demo, estimator verification and actual loopback HTTP byte
preservation pass. Upgrade from the verified published 1.24.0 wheel and rollback
preserve all 19 representative pricing rows and the exact configuration hash.
The final committed archives will be rebuilt, checked and hashed before tagging.

The separately prepared Pro 0.2.0 wheel declares exactly OSS 1.25.1 and TIP-1.0.
The actual installed pair passes its daemon handshake and preserves the
unlicensed reroute boundary. All 52 affected Pro tests pass. An initial source
test command referenced the preserved 1.25.0 checkout and correctly produced a
compatibility rejection; correcting that command resolved the mismatch without
a product change. The failed command remains recorded.

Broad platform and human-outcome validation is deferred under the minor release
cadence. No demo supplies a real user's measured savings receipt. Production
reroute priors and human comprehension outcomes remain unestablished.
