# TokenPak v1.19.0 Release Log

## Scope

This minor release adds the immutable `session-economics/1` Python contract and
the deterministic `/v1/messages/session-economics` proxy endpoint. The endpoint
derives runway locally without making provider calls, preserves provider usage
and pricing provenance, and treats missing usage as unknown rather than zero.
Runway is bounded conservatively by context, request or dollar budgets, and
rolling caps. The release also stabilizes re-ingested Pak envelopes, repairs
monitor-writer lifecycle behavior, and isolates proxy test listeners on
ephemeral ports.

The release candidate starts from staging commit
`6f8335fc6965a98d178f2872ba5a8ef07b5ed784`. Validation, publication, and
post-publication stages remain pending.

## Classification and compatibility

- **SemVer:** MINOR because the release adds backward-compatible public Python
  and HTTP capabilities.
- **Risk:** full-conservative because the accumulated release delta is large and
  spans shared proxy/core behavior plus public documentation.
- **Public API:** 4,663 symbols versus 4,634 in v1.18.5: 29 additions and zero
  removals.
- **Compatibility ruling:** keep all 29 session-economics additions as the
  supported `session-economics/1` surface. No existing public symbol is removed
  or reclassified.
- **Breaking changes:** none identified.
- **Deprecations:** none introduced.

## User-visible behavior

- Contract values distinguish measured, estimated, unavailable, and error
  states and carry provenance rather than collapsing absent facts into a
  number.
- Runway reports its binding constraint and conservative guard state. Missing
  attribution, stale pricing, or insufficient growth history can yield
  learning, unavailable, or error output by design.
- The session-economics endpoint is observational and makes no provider call.
