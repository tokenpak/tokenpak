# TokenPak v1.25.3 Release Log

## Scope

In-flight spend remains reserved until its queued telemetry row commits.
Successful commits refresh rolling-cap usage before retiring the reservation,
so a concurrent admission cannot observe a gap between pending and recorded
spend. Failed writes retain the existing bounded reservation. A notification
failure does not cause a committed row to be inserted again.

Session economics displays pair burn-direction arrows with words and expand
context-limit labels. Shared consumers retain the same display and machine
contract; provider request and response bytes are unchanged.

## Compatibility and limitations

- The package advances from 1.25.2 to 1.25.3. Existing call signatures remain
  usable. The monitor accepts an optional internal admission ticket, and the
  spend guard gains a commit notification helper. No telemetry column, TIP
  version, configuration or stored-data migration changes.
- Reservations retain their existing process ownership, projection and expiry
  limits. This correction does not add a live cross-process guard snapshot or
  claim that the forecast includes every pending request.
- Exact normative docs and registry pins are unchanged. Historical costs and
  populated pricing databases are preserved.
- The separately distributed Pro 0.3.0 package declares OSS 1.25.3 and TIP-1.0
  compatibility. Its new absolute-price input API and generator pricing fixes
  are validated and published separately before a paired rollout.
- Production recommendations still require complete measured inputs and
  eligible empirical priors. Synthetic tests do not supply empirical or human
  comprehension evidence. Older comprehension materials retain their original
  display version and cannot stand in for this release's changed text.

also need Pro 0.3.0. Verify both installed versions, package origins and daemon
