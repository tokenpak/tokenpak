# TokenPak v1.18.2 Release Log

## Scope

This compatible patch restores configured custom-provider loading, endpoint
routing, and outbound credential delivery; corrects compression/configuration
claims to match the default HTTP proxy; and adds conservative changed-surface
CI while pinning every third-party workflow action to a full peeled commit SHA
and requiring checksum verification before direct GitHub release downloads are
used, while repairing release-rehearsal dependency declarations. Validation
also identified and corrected prompt-path Companion persistence, monitor queue
shutdown, and telemetry schema initialization defects. The release includes
directly affected tests, documentation, version metadata, and generated release
snapshots.

Out of scope: pricing, billing, public or operator-run storage migrations, TIP
wire changes, unrelated feature work, and replacement of existing required
staging contexts. Private local SQLite plumbing is in scope and upgrades
additively and automatically.

environment and runtime-pointer backup until closeout.

## Compatibility disposition

- No breaking change is intended.
- No public data, configuration, registry, or storage-schema migration is
  required. Existing private local Companion, monitor, and telemetry databases
  apply idempotent additive columns and indexes automatically, preserving
  legacy cost rows while filling missing columns in place.
- The generated Python public-symbol set must remain unchanged.
- `tokenpak doctor --json` gains an additive `custom_providers` object with
  `configured`, `registered`, and `error` fields.
- Existing provider configuration continues to parse. Invalid provider entries
  remain non-fatal and are now distinguishable from successful registration.
  Routable custom providers may omit `models`; `api_key_env` names the optional
  outbound credential source. Any non-empty client upstream credential wins.

## Known limitations

- `TOKENPAK_COMPACT`, `compression.enabled`, and the threshold are compatibility
  settings for the legacy explicit helper. They do not activate body compaction
  in the built-in default HTTP proxy path.
- Risk-selected CI is additive for v1.18.2. Existing required staging contexts
  remain authoritative until separate parity evidence supports migration.
- Custom providers must use a supported built-in wire format. Endpoints with
  userinfo, fragments, or credential-shaped query parameters and invalid format
  entries are skipped and reported rather than partially registered. A
  configured endpoint query is treated as fixed routing policy and wins a
  same-name request query field.

- **What dragged:** a GitHub Actions infrastructure outage stalled exact-head
  CI mid-flight (three runs cancelled, re-run to green), and fleet-wide
  runtime convergence trailed publication by roughly five hours awaiting
  deployment-host access.
- **What broke or nearly broke:** the structural safety scan flagged the
  product's own documented vault-index default (triaged false positive;
  pattern refinement follows separately); a post-publish version smoke read a
  stale version by running inside a source checkout (`sys.path` cwd
  shadowing) before being rerun from a neutral cwd; host swaps severed pooled
  upstream streams that the inbound-only in-flight gate did not count.
- **Carry-forward action:** refine the vault-path structural pattern; extend
  the pre-swap in-flight gate to count upstream-side streams on every host;
  advance the documentation revision pin at each release rather than
  deferring it; always run version smokes from a neutral cwd.
