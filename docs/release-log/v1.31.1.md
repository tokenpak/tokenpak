# TokenPak v1.31.1 Release Log

## Scope

This patch release stops TokenPak from stalling sessions that nobody is
watching. Each item fixes behavior that blocked, stranded or silently
unprotected a session.

1. **Spend Guard image estimates and approvals (#369).** Images were counted
   as encoded text, so sessions with screenshots were projected at several
   times their real size and blocked far below their limits. Images are now
   estimated from their dimensions, and later estimates in a session start from
   the provider's reported usage. Approvals no longer strand a session; hard
   stops are unchanged.
2. **Status-line writer CPU (#368).** The writer backs off while its inputs are
   idle, bounds cache cleanup, and exits when its session ends.
3. **Windows launchers in the package, one proxy address for every launcher
   (#370).** The native Claude and Codex launchers existed only as local
   patches, so a reinstall or upgrade removed the entry point Windows sessions
   start through. Every launcher, Windows or POSIX, Claude or Codex, now reads
   the proxy address the same way at launch: `TOKENPAK_PROXY_URL`, else
   `TOKENPAK_PORT` on `127.0.0.1`, else the default port. Health probes take
   their timeout from `TOKENPAK_PROXY_PROBE_TIMEOUT_SECONDS` and are bounded in
   wall-clock time.
4. **`tokenpak claude` fails closed (#371).** A missed proxy probe used to start
   Claude directly with no spend guard, no telemetry and no message. The
   launcher now waits up to `TOKENPAK_PROXY_WAIT_SECONDS` (default 10), then
   exits with code 7 and one line. The wait holds however the proxy answers:
   each probe ends at its timeout or at the end of the wait, whichever comes
   first. `TOKENPAK_ALLOW_DIRECT=1` allows a direct start, and the banner says
   so.
5. **Codex session lease on Windows (#372).** POSIX permission calls and checks
   now apply only where the platform has POSIX permission bits.
6. **Session-start checks and the shared provider breaker (#373).** The first
   one-token startup check from each identified client session no longer
   counts toward the per-provider breaker, so a few sessions starting together
   cannot refuse every session's traffic for the cooldown. The exemption is
   bounded: at most one per session per hour and 60 per provider per hour (both
   settings), none without a session identity, and every other refusal,
   including a repeat from the same session, counts as before. Session
   identities are held only as keyed digests.

## Upgrade and rollback

**OSS only, no Pro installed.** Run `pip install --upgrade tokenpak`. The
upgrade is package-only: no migration runs, no configuration change is needed,
and no file is moved. If you run `tokenpak claude` without the proxy, start it
with `tokenpak start` or set `TOKENPAK_ALLOW_DIRECT=1`.

**Rollback.** `pip install tokenpak==1.31.0`. 1.31.1 writes no new state that
1.31.0 cannot read.

## Pairing with TokenPak Pro

TokenPak Pro 0.6.1 declares `tokenpak==1.31.0` as an exact requirement. Do not
upgrade `tokenpak` alone on a host with Pro installed: pip does not stop it,
`pip check` then fails, and Pro refuses to run against the newer package. Pro
hosts stay on 1.31.0 until a Pro release that accepts 1.31.1 is built, tested
against the exact 1.31.1 release source, and published. Upgrade the pair
together.

## Public API snapshot

The snapshot is regenerated from `main` with #370, #371, #372 and #373 merged,
because this release lands after them: 4,966 symbols, 42 added and 1 removed.
The changeset `.changeset/v1311-api-snapshot.md` lists them.

- Added: the three Windows launcher modules (21), `is_startup_check` in the
  proxy's circuit breaker, the Spend Guard `media`, `approvals` and
  `usage_anchor` modules and one estimator name (14), and six module-level
  names in `tokenpak.status.worker`.
- Removed: `tokenpak.status.worker.valid_session`, an incidental import that
  the status-writer change (#368) dropped. Ruling: remove. The function is
  unchanged at `tokenpak.status.binding.valid_session`, and nothing in TokenPak
  or TokenPak Pro imports it from `tokenpak.status.worker`.

If any of those pull requests changes before it merges, rebase this branch and
regenerate the snapshot with `make api-snapshot`.
