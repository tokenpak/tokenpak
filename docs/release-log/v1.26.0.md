# TokenPak v1.26.0 Release Log

## Scope and compatibility

Authenticated native guard and workload snapshots expose bounded facts for an
explicit session. Optional durable accounting coordinates pending reservations
with committed usage and binds supported charges to observed workload prices.
Frozen session history preserves the selected rows through the shared economics
interface. Existing scalar pricing and default-off forwarding behavior remain.

Durable accounting is still opt-in. Its reads cannot supply missing price,
provider, cache, region or tier evidence, and old estimates are not silently
repriced. Unsupported or unpriced history remains unavailable for monetary
admission. See [request observations](../request-workload-observations.md) and
[workload pricing](../workload-pricing.md) for the precise supported scope.

The separately distributed Pro0.4.0 requires this OSS1.26.0 release and TIP-1.0.
It adds explicit native policy/history/target resolution, prepared context
bundles, observed-reference measurement, fresh confirmation and decline records.
These commands require complete applicable facts and eligible priors. They do
not launch a new session, transfer execution or enable automatic rerouting.
Measured comparison bounds are scenario envelopes, not calibrated confidence
intervals, total future bills or verified savings.

## Upgrade and rollback

Back up configuration, pricing databases, accounting history and private Reroute
stores before upgrade. Stop writers or use a consistent database-backup method;
copying an active SQLite file without its transaction state is insufficient.
Retain the previous installed artifacts and backups through the observation
period. Schema additions preserve existing rows and settings; an existing
pricing database only receives new bundled bands through explicit seed refresh.

Install `tokenpak==1.26.0`, retaining the extras your application already uses.
For the standard service profile, install
`tokenpak[serve,tokens,telemetry]==1.26.0`. Existing Pro installations also require
the matching Pro0.4.0 artifact through their existing distribution channel.
Verify package versions and import origins from the actual runtime interpreter,
then check CLI, proxy and daemon readiness. Keep runtime opt-ins unchanged unless
their prerequisites and operator intent have been reviewed separately.

Rollback restores the verified OSS1.25.3 / Pro0.3.0 pair with its pre-upgrade
settings and consistent state backups. Retain newly created state separately
before restoring older backups; earlier versions do not implement the new
native record semantics. No released tag or artifact is replaced.

## Known security finding

This release accepts the open High NLTK finding
[GHSA-8mgp-746c-j5xp](https://github.com/advisories/GHSA-8mgp-746c-j5xp) in the
optional compression/full and llamaindex paths. No patched NLTK release is
currently listed. The base and standard service profiles do not select NLTK;
optional embedding applications retain the exposure described in
[SECURITY.md](../../SECURITY.md). Avoid untrusted NLTK model import/export paths
and do not rely on pathsec to confine those APIs. This release-specific accepted
finding stays open and requires reassessment before the next release. All other
release checks remain required.

publication and deployment are pending. This preparation record claims none of

from their actual publication. Preserve preceding observation results and open
