# TokenPak v1.28.0 Release Log

## Recorded usage and session history

Session economics can show the provider-observed usage subtotal and the number of
measured requests even when full-session totals are unavailable. The optional
`recorded_usage` field includes the observed subtotal, complete request count and
failed-request count. Terminal views label the subtotal and its coverage. Costs
derived from a rate card remain estimates; they are not provider bills.

Failed requests and missing measurements stay in full-session accounting and
forecast eligibility. Explicit recorded `xhigh` effort with supported provenance
forms its own forecast cell. Unknown or conflicting effort remains separate.
The release does not supply missing calibration history or numeric forecasts.
Shared line, block and dashboard views label forecast-derived guard runway as
an estimate, consistently with the companion footer and the observed-value legend.

Codex lifecycle hooks use Python's built-in SQLite support to register native
sessions and recover completed native turns. The intake preserves fork boundaries
and large transcript records; replay does not duplicate turns. Native transcript
files remain intact. Journal entries recover native identifiers, model metadata
and timestamps without inventing usage, cost or completion evidence. Session
history lists show actual journal entry counts.

## Upgrade and rollback

Back up configuration and state with consistent database backups and retain the
previous artifacts. Install `tokenpak==1.28.0`, preserving existing extras. The
standard service profile uses `tokenpak[serve,tokens,telemetry]==1.28.0`. Restart
the relevant services after active work finishes and use a new companion launch
to load updated hooks. Preserve running native client sessions.

Pro users also need the separately distributed Pro 0.4.3 package. It supports
OSS 1.26.0 through 1.28.0 with TIP-1.0. Pro 0.4.2 supports only OSS versions
through 1.27.0. Upgrade the pair together. The optional economics field is
compatible with existing v1 readers; the frozen usage schema and historical
ledger rows remain intact. No state migration is required by these changes.

For the standard service profile, roll back with:

```bash
python -m pip install "tokenpak[serve,tokens,telemetry]==1.27.0"
```

Retain any other extras used by the installation. Paired installations also
restore Pro 0.4.2 from its existing authenticated distribution before restarting
the relevant services. Preserve newly captured state and native transcripts
before restoring a backup; these changes require no state cleanup. Existing
public tags and artifacts are never replaced. No breaking changes or
deprecations are introduced by this release.

## Known limitations and security

Forecasts still require eligible homogeneous histories and scored observations.
Recovered journal turns and local fixtures do not establish calibrated forecasts,
independent outcomes or human comprehension. Missing provider measurements remain
unavailable. No provider session is automatically transferred or rerouted.

This release accepts the open NLTK
[GHSA-8mgp-746c-j5xp](https://github.com/advisories/GHSA-8mgp-746c-j5xp) and
Accelerate [GHSA-4j2p-28q2-5m79](https://github.com/advisories/GHSA-4j2p-28q2-5m79)
optional-dependency findings for this release only. Both are High under CVSS
v3.1; the Accelerate advisory separately lists Moderate severity under CVSS v4.
No verified published fix is available. The base install excludes both packages.
Optional integrations must avoid untrusted model paths and checkpoint repositories
and cannot rely on these APIs for filesystem containment. See
[SECURITY.md](https://github.com/tokenpak/tokenpak/blob/main/SECURITY.md) for affected extras and limitations. The findings
remain open and must be resolved or reassessed before another release; all other
checks remain required.

## Validation and completion

Validation covers the merged history, count and usage changes, including journal
replay, fork isolation, request denominators, effort-cell identity, old-reader
compatibility and terminal presentation. The release also requires exact-candidate
CI, artifact and installed-version checks, CLI/proxy smoke, paired compatibility,
and upgrade/rollback. Publication, deployment and the 24-hour observation period
remain separate milestones.
