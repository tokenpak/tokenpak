# TokenPak v1.29.0 Release Log

## Native token observations and first-session reliability

This candidate adds opt-in, authenticated native token observations with explicit
request coverage, bounded reservations and response-completion evidence. Token
counts remain separate from billed cost, calibrated forecasts and accepted task
outcomes. Additive database migrations preserve historical accounting evidence.

Fresh companion journals now record the first Claude prompt when an external
SQLite executable is absent. The managed hook uses the selected interpreter and
journal directory. The MCP server reports startup and malformed-input diagnostics
on stderr while keeping JSON-RPC on stdout. Dispatch help describes its optional
dependencies and the remaining station execution and delivery limitations.

## Upgrade and rollback

The candidate pair is OSS 1.29.0 and Pro 0.5.0, using TIP-1.0. Pro 0.5.0 declares
OSS 1.26.0 through 1.29.0 compatibility; native-token measurement needs OSS 1.29.0.
Pro 0.4.3 supports OSS only through 1.28.0. Upgrade the packages together once
both releases are published through their existing distribution channels.

Back up configured local databases and configuration before upgrading. The
database changes are additive and do not relabel historical rows as native
measurements. Schema migration is one-way. Rollback restores OSS 1.28.0 and Pro
0.4.3 together with the pre-upgrade database backup. Preserve a separate copy of
post-upgrade state before restoring; do not delete new evidence or try to reverse
the schema migration in place.

## Validation and open requirements

Candidate wheel and source builds pass package metadata checks. An isolated
installation of OSS 1.28.0 / Pro 0.4.3 was upgraded to the candidate pair, rolled
back with its pre-upgrade backup, and upgraded again. Configuration, journal
entries and historical accounting rows were preserved; new state was retained
separately during rollback. Missing licenses still refuse entitled commands.

The migration verifier now creates each historical schema atomically, avoiding
per-statement disk commits while preserving its DDL restrictions. Its 30 focused
checks pass with the existing timeout, including rollback after a rejected
declaration. Current-version documentation examples were also corrected.

This is release preparation, not a published release or a deployment receipt.
A fresh September 21 audit covered all 213 locked package/version
pairs and 39 resolved release-tool dependencies, with no yanked files. The two
open findings affect optional NLTK and Accelerate dependencies; both receive
High treatment under CVSS v3.1. This release accepts those findings for this
release only with the limitations in [SECURITY.md](https://github.com/tokenpak/tokenpak/blob/main/SECURITY.md) and the
[changelog](https://github.com/tokenpak/tokenpak/blob/main/CHANGELOG.md#1290--2026-09-21). The audit is not clean, and the
previous release's acceptance is not carried forward. The standard installed
candidate pair excludes both affected packages and their optional consumers.

Real provider outcomes, per-model calibration, human comprehension and customer
retention remain separate requirements. This release does not establish billed
subscription savings or enable automatic rerouting. Payments and self-service
checkout are outside this candidate.
