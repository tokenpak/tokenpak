# TokenPak v1.25.0 Release Log

## Scope

The release adds `tokenpak savings --verify`, using an independent tokenizer
over a packaged fixture corpus. It reports divergence from the existing byte
estimator without changing recorded savings or claiming to recount requests
whose text was not retained.

Pricing catalogs include current model identifiers, explicit units, provenance,
and a preserve-first refresh path. Legacy numeric interpretations and existing
cost history remain intact. Forecast inputs preserve model and effort identity;
mixed histories and unsupported effort values remain unavailable for homogeneous
calibration. Session inactivity is not evidence of task completion.

Automatic vault retrieval has a configurable 2,000 ms deadline and a two-worker
bound. Timeouts and occupied-worker backlogs forward original request bytes and
produce explicit degradation receipts. All forwarding builders apply the same
internal-header predicate.

Companion and optional Pak-builder changes preserve role-bearing conversation
turns, isolate concurrent native launches, compose custom hooks, and retain
semantic journal provenance. Customized skills remain preserved during managed
upgrades. Session displays label estimates and distinguish guard runway from
session remainder.

Installed distributions carry canonical release metadata. The optional local
daemon must pass a bounded loopback health/version handshake with valid declared
compatibility before a client reports it active. Missing or incompatible daemon
metadata is shown as a diagnostic; the separately distributed Pro package is
not bundled into this OSS release.

## Compatibility and limitations

- The package version advances to 1.25.0. TIP-1.0 and its exact normative docs and
  schema pins remain unchanged.
- Pricing refresh preserves stored cost rows and old-date numeric interpretation.
  The existing reprocess pricing-version override remains ineffective.
- Forecast calibration, measured production reroute policies, and human
  comprehension outcomes require their own evidence. These source changes do
  not enable default-on rerouting or establish product-outcome claims.
- Optional heavy dependencies retain their previously documented limitations;
  dependency audit results are recorded before release readiness is declared.

## Upgrade

```bash
python -m pip install --upgrade "tokenpak==1.25.0"
```

Install `tokenpak[tokens]==1.25.0` to use independent estimator verification.
Existing state and custom configuration are retained. Before upgrading a paired
daemon installation, install a Pro version whose declared compatibility includes
this OSS version and TIP-1.0.

## Rollback

```bash
python -m pip install --upgrade "tokenpak==1.24.0"
```

Keep the previous environment and configuration backup until validation and the
post-deploy watch finish. Artifact upgrade and rollback proof is pending in this
