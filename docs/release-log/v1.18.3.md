# TokenPak v1.18.3 Release Log

## Scope

This compatible patch reduces the token overhead the companion itself adds to
agent sessions: guidance surfaces (generated Codex AGENTS.md section, Claude
launcher prompt fragment, MCP tool descriptions, companion guide) stop
directing agents to spend model round-trips on accounting that hooks already
perform out-of-band; `estimate_tokens` MCP results are compacted to the fields
an agent acts on while keeping a short estimator disclosure; and the `lean`
companion profile advertises only core MCP tools in `tools/list` while
dispatch stays unfiltered. It also makes the companion session label plain
text (robust to host-side control-byte sanitization) and hardens the delta
leak gate, private-path scan, and release workflow quoting.

Out of scope: pricing, billing, storage migrations, TIP wire changes, any
wire-mutating request optimization (separately gated design work), and the
open dependency-update wave (deferred with reason in the captain packet).

Classification note: the release adds one additive public symbol
(`active_tools` in the companion MCP package, re-exported by its server
module). A strict SemVer reading of an added public symbol indicates MINOR;
the operator explicitly classified this release patch-class with that
evidence on record (designation and verbatim authorization text recorded in
internal release governance, 2026-08-07). The tension is recorded here and
in the governance record rather than resolved silently.

Changelog reconciliation performed at cut: the pak canonical-schema entries
(`pak create` schema_version 2, `pak migrate`, legacy readability) were found
in [Unreleased] while their code is reachable from the v1.18.2 tag — a
v1.18.2 changelog under-report. They were relocated into the 1.18.2 section
as a marked addendum, not re-shipped under 1.18.3.
